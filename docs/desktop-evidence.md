## 0.2.3：运行内存与查询性能

归档、增量采集和查询共享不可变观测；移除长期保存的逐条 JSON 副本。归档初次及跨连接失效时使用 SQLite 迭代器，本进程提交后直接更新内存记录；回滚清空缓存并重载，保留 WAL 外部写入检测。归一与去重仅复制有修改的记录，整理与排序结果跨时间范围复用，新增观测、修订或命名规则变化使缓存失效。时间范围与未来时间过滤继续按实际时间计算。

界面复用三种 ICU 日期格式器，DSH 转换复用仍有效的原始对象，未完成 JSONL 的少量尾部字节不再长期引用整块 256 KiB 缓冲。界面 5 秒、后台 15 秒采集频率保留。没有强制 GC、硬限堆内存或清空工作集。

固定同一份 30,681 条真实用量元数据，去重后 30,680 条请求，以隔离的 home、profile 和账本/JSONL 副本运行。两个版本各测两次，查询交替使用全部/今天，每次间隔 1.1 秒以越过响应缓存；每种窗口状态取 8 次一秒间隔采样的中位数，再对两次运行取平均。统计全进程私有内存，包含主进程、GPU、网络、数据服务与界面进程。

- 模型页私有内存：479.4 → 453.7 MiB，约降低 5.4%。
- 请求流水页：412.5 → 369.0 MiB，约降低 10.5%。
- 收起到托盘：389.4 → 363.2 MiB，约降低 6.7%。
- 切换范围的接口耗时中位数：44.2 → 14.4 ms，约减少 67.5%。
- 追加一条新请求后的首个查询：149.1 → 64.3 ms；补读确认仅新增一条，没有漏计或重复。
- 显示窗口并收到刷新响应：65.7 → 21.4 ms。

以上是固定本机负载，不能推广为所有电脑或完整原始客户端冷扫描的结果。首轮新版从刚生成的未解包目录打开用时 8,057 ms，复测 1,216 ms；旧版安装目录两次为 1,542 / 1,420 ms，因此不宣称冷启动整体提速。GPU 及 Electron 运行时仍有固定开销，实际数据量、窗口尺寸与系统缓存会影响占用。原始结果及汇总位于 `logs/performance/{baseline,baseline-repeat,optimized,optimized-repeat,comparison}.json`。

新增不可变共享记录、事务失败回滚、归一不污染证据、预整理账本跨时间边界与别名一致性测试。

## 0.2.6：采集缓存与大文件稳定性

- DSH 已入库记录释放，序号独立于待提交数组保存，未完成行与压缩帧继续从原游标读取。补齐 Zstandard 校验尾部尚未写完的处理，避免把不完整帧交给解压器。
- ZCode / OpenCode 使用 SQLite 迭代器转换元数据，成功入库后释放记录数组，只缓存数据库及 WAL 的变化签名。文件变化后重读；失败或暂停时不提前释放待入库记录。
- 修复相同内容的新对象仍触发账本重建的问题；后台提交改变观测时立即释放旧的归一账本及时间范围快照，避免隐藏窗口长期保留旧修订。覆盖元数据更新不触发整份账本重新归一。
- JSONL 释放记录后继续保留备用 ID 的累计序号；否则无原始 ID 的新增请求可能覆盖旧调用。释放阶段最多并发 32 个文件状态检查。
- 大文件采集逐条追加事件，移除把整份数组展开为函数参数的路径；CSV 每次拉取最多生成 128 条，遵守 HTTP 背压和取消。主进程后台采集请求消费响应体，及时释放连接资源。
- 移除重复的 DSH 目录遍历和只在采集间隔之间短暂有效的目录缓存，复用共享文件扫描器；移除没有使用的 SQL 投影字段。React 界面、软件绘制、5 秒界面刷新及 15 秒后台定时器保留。

33 项单元测试通过，包括单文件 14 万条来源记录、增量 ID、DSH 明文/压缩缓存释放、未写完的压缩校验、数据库修订与原 Token 定义、事务失败、跨连接写入，以及分批 CSV 的完整性、HEAD、空结果和取消。Lint、严格未使用符号检查与桌面生产构建通过。
